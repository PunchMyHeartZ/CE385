## ข้อ 2 — ชนิดข้อมูลใน JavaScript (`workshop1-2.js`)

**โจทย์:** ประกาศตัวแปรครบทุกชนิด (string, number, boolean, undefined, null, array) แสดงค่าและ `typeof` พร้อมทดสอบ typeof null, NaN และการแปลงชนิดข้อมูล

**หัวข้อที่ใช้**
- ตัวดำเนินการ `typeof` ตรวจชนิดข้อมูล
- `Number()` แปลง string เป็น number, `Number.isNaN()` ตรวจ NaN
- `===` เทียบทั้งค่าและชนิด (ไม่แปลงชนิดให้)

**สิ่งที่น่าสนใจ**
- `typeof null` ได้ `"object"` ซึ่ง**ไม่ถูกต้อง**ตามความจริง (เป็น bug เก่าแก่ของ JavaScript เพราะ null คือค่าว่าง)
- `typeof NaN` ได้ `"number"` และแปลงข้อความ `"abc"` เป็นเลขไม่ได้จะได้ `NaN`
- `"20" === 20` เป็น `false` แต่ `Number("20") === 20` เป็น `true`

## ข้อ 3 — เครื่องคิดเลขคะแนน (`workshop1-3.js`)

**โจทย์:** คำนวณคะแนนรวมของนักศึกษาตามเกณฑ์รายวิชา CE385 (Workshop 48/60, Attendance 9, Project 17, Midterm 15, Final 24)

**หัวข้อที่ใช้**
- `const` เก็บเกณฑ์คงที่ (60, 20, 100, 80) — ห้ามพิมพ์ตัวเลขดิบกลางสูตร
- Template Literal แสดงใบสรุปคะแนน
- `.toFixed(2)` แสดงทศนิยม 2 ตำแหน่ง (ระวัง: คืนค่าเป็น string ห้ามนำไปบวกต่อ)

**สูตรที่ใช้**
- Workshop แปลงแล้ว: `(48 / 60) × 20 = 16.00`
- คะแนนรวม: `16 + 9 + 17 + 15 + 24 = 81.00 / 100` (81.00%)
- ขาดอีกถึง 80: `80 − 81 = -1.00` (ติดลบ = เกินเป้าแล้ว)

## ข้อ 4 — ตัดเกรดจากคะแนน (`workshop1-4.js`)

**โจทย์:** เขียนฟังก์ชัน `toGrade(score)` ตัดเกรด A-F พร้อมตรวจข้อมูลนำเข้า และทดสอบ 13 ค่าด้วย `for...of`

**หัวข้อที่ใช้**
- `if / else if` ตัดเกรด — ต้องเรียง**จากคะแนนมากไปน้อย** เพราะเงื่อนไขแรกที่เป็นจริงจะจบทันที จึงเช็คแค่ขอบล่าง (`>= 80`) โดยไม่ต้องเช็คขอบบนซ้ำ
- ตรวจข้อมูลก่อนเสมอ: คะแนน `< 0` หรือ `> 100` → ไม่ตัดเกรด (คืน `null`)
- `for...of` วนทดสอบ array ของคะแนน

**ผลการทดสอบกรณีขอบ:** `80 → A` (ไม่ใช่ B+) และ `79 → B+` (ไม่ใช่ A) · `-5, 120 → คะแนนไม่ถูกต้อง`

## ข้อ 5 — ระบบสั่งอาหาร (`workshop1-5.js`)

**โจทย์:** คิดราคาเมนูด้วย `switch` — `getMenuPrice(menu)` + `getSizeMultiplier(size)` แล้ววนคิดราคารวมทั้งบิล

**หัวข้อที่ใช้**
- `switch` เทียบค่าแบบ `===` เป๊ะ ๆ (ใช้ `.trim()` กันช่องว่างหน้า/หลัง)
- **Fall-through โดยจงใจ:** ข้าวผัด / ข้าวมันไก่ / ข้าวหมูแดง ราคา 50 เท่ากัน จึงรวม 3 case เข้าด้วยกันแทนการเขียนซ้ำ
- มี `default` ทุก switch (เมนูไม่มีในรายการ = 0 บาท)
- สูตรต่อรายการ: `ราคาเมนู × ตัวคูณขนาด × จำนวน` เช่น ผัดไทย (พิเศษ) x2 = 60 × 1.5 × 2 = **180 บาท**

**ผลลัพธ์:** ออร์เดอร์ 5 รายการ (มี "ส้มตำ" ทดสอบ default) รวมทั้งบิล **695 บาท**

## ข้อ 6 — ระบบตรวจสอบสิทธิ์ (`workshop1-6.js`)

**โจทย์:** ฟังก์ชัน `login(inputUser, inputPass, role, isActive, age)` ตรวจตามลำดับ: ตัวตน → บัญชีระงับ → อายุ → แยกสิทธิ์ตาม role

**หัวข้อที่ใช้**
- `===` เทียบค่าเป๊ะ ๆ ทุกจุด, `||` ตรวจ username/password ผิดอย่างใดอย่างหนึ่ง
- ฟังก์ชัน `return` ข้อความผลลัพธ์ ไม่ `console.log` ข้างใน แล้วค่อย log ตอนเรียกใช้
- ทดสอบ 6 กรณี: สำเร็จ (อาจารย์/นักศึกษา), รหัสผ่านผิด, ชื่อผู้ใช้ผิด, บัญชีถูกระงับ, อายุไม่ถึง

**คำตอบท้ายข้อ**
1. **ทำไมตรวจ username/password ก่อน role?** role คือข้อมูลหลังพิสูจน์ตัวตนสำเร็จ (authorization) — ถ้าตรวจ role ก่อน คนแปลกหน้าแค่ส่ง `role = "อาจารย์"` มากับมือก็ได้สิทธิ์ผู้ดูแล ทั้งที่ตัวตนยังไม่ได้ยืนยัน
2. **ถ้าย้าย "อายุไม่ถึงเกณฑ์" ขึ้นเป็นข้อแรก?** ระบบจะเปิดเผยข้อมูลให้คนที่ยังไม่ได้พิสูจน์ตัวตนมากเกินจำเป็น (information leak) เช่น คนที่กรอกรหัสผิดก็รู้ว่าระบบมีเกณฑ์อายุ 18 ปี — หลักความปลอดภัยคือตรวจตัวตน (401) ก่อนเสมอ
